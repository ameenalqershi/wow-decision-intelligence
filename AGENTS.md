# Working agreements

Start with CONTRIBUTING.md and planning/roadmap.md. GitHub issues are the work ledger. Claim an unclaimed, dependency-ready item before editing. Use an isolated worktree. For a continuation, inspect existing issue comments, reservation tag, branches and dirty worktrees. Never take over another claim silently or overwrite unfinished work.

Keep domain, compiler, solver adapter and independent verifier separated. Preserve source and tenant identity across changes. Every Optimal assertion needs a declared proof or solver evidence level. An experiment must state the baseline, data, budget and acceptance conditions. Recompute evidence when a semantic input changes. DML data must never execute arbitrary code. Do not introduce mandatory paid services, Python production components or dependencies on WOW ERP. Attach test evidence and check downstream assumptions before closing an issue.
