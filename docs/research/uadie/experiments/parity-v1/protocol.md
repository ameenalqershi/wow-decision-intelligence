# Prospective parity v1 experiment protocol
Frozen candidate source commit: 880d6661360009190fd8c6174797107e6c34be3c.
This is a small finite binary study, not production qualification. Previous 3,360 raw rows remain unchanged.
Arms: full, warm, partition, reuse, box, pair, parity (same component fallback), parity-warm (fallback ablation). Primary comparisons: parity vs pair (same fallback), parity-warm vs warm (incremental gate overhead). Include a new native CP-SAT comparator separately only after confirming native availability and verifying model translation. No tuning on holdout.
Development: seeds 182000–182007, 6–8 variables. New seed holdout: seeds 283000–283007, 8–12 variables. Same newly authored generator, not independent-family holdout. Ten families, 80 revision pairs per arm and split. Includes paths, stars, even cycles, odd-cycle contradiction, mixed cardinality, removed rows, disjoint, isolated, tightening, large signed changes. Some shift cases deliberately target the exact parity premise, so family-balanced aggregate is descriptive, not a representative workload.
Each process is pinned to a single permitted core; max 15 s/launch; overall 300 s per split; systemd user scope memory ceiling 768 MiB and CPU quota 100%; serial launches. Verify limits from systemd; if no kernel limits are available do not claim resource qualification. Stop on first nonzero exit, invalid row, or resource exhaustion; retain stdout/stderr and metadata. Three deterministic rotated arm orders on each split. Compare median total revised candidate wall (includes verification), P10/P90, per-family hits, current-thread allocations, peak process RSS; separately report external audit time and native comparator timing. Repeated observations of the same seed are not independent. No speed claim without prospective independent family and native comparisons, confidence intervals and representative scales. Correctness requires every oracle verdict and witness match; any counterexample blocks promotion. An accepted candidate remains a research prototype, not a production certificate kind. On these tiny models, do not promote over warm unless the paired verified wall median improves and memory overhead is justified. No promotion based on transfer rate alone.
