# Certified square assignment route
Admission: n=k^2 Boolean variables, k>=3, exactly 2k equality rows of size k with rhs=1, no other constraints, graph/fixes. Each variable belongs to two rows. Producer colors row-incidence graph and requires complete bipartite k-by-k edges, one distinct source variable per cell. Independent verifier checks left/right row indices form a partition of all rows, the matrix entries form a permutation of all source variable indices, each original row is exactly its corresponding row/column of the matrix, and all bounds are equality 1. Therefore original feasible assignments correspond exactly to permutations; no side constraints discarded. For costs c_ij, primal x is a permutation. Dual potentials u_i,v_j satisfy u_i+v_j<=c_ij for every cell. For any feasible x, sum c_ij x_ij >= sum(u_i+v_j)x_ij = sum u_i+sum v_j. If matched cells attain equality, primal cost equals dual bound, hence global optimum for original source, including its LP relaxation. Independent verifier uses Int128 for exact dual feasibility, primal/dual equality, all source bits and reconstruction; common original witness verification also used. Source digest is evidence binding, not sole structural proof.
Producer uses known Hungarian primal-dual method, Int128 intermediate arithmetic and checked conversion of potentials. A dedicated native assignment result can instead be certified by difference constraints v_j-v_match(i)<=c_ij-c_i,match(i), u_i=c_i,match(i)-v_match(i). Relaxation from all-zero potentials for at most k passes obtains feasible v if no negative cycle; any further improvement on pass k rejects. The same independent verifier proves equivalence and optimum for both. Complexity discovery O(k^2) storage/time (assuming admitted source); Hungarian O(k^3), extra working vectors O(k), input/map O(k^2); dual recovery O(k^3), checker O(k^2 log k) due sorting and exact cost checks. No novelty claim: Kuhn 1955 https://doi.org/10.1002/nav.3800020109 ; specialized OR-Tools API https://or-tools.github.io/docs/dotnet/classGoogle_1_1OrTools_1_1Graph_1_1LinearSumAssignment.html . Sparse/rectangular/side-constrained assignments and general mixed integer models are unsupported; abstain to original qualified engine. This is a new research route, not yet integrated into G16's adaptive dispatcher.
