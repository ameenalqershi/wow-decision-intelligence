# S04 — Independent original-model verification

Scope #29 / REQ-S04 / DIR-S04-1 / TC-S04-A. The component depends only on public UDIR, S01 records and the V01 Manufacturing.Data source contract, never compiler, presolve, lowering, solver adapters or research implementations. It does not infer infeasibility from a bad witness, prove optimality from a good witness, or accept mathematical status from a solver as independent proof. S05 owns bound/certificate classification.

OriginalVerifier accepts the trusted registry scope (tenant, model, revision, run, SHA-256 of frozen UDIR envelope), the original UDIR and frozen M04 measurement catalog, and the S01 candidate. Candidate must match the full scope. Every variable must appear exactly once using ordinal identity; candidate cannot override parameters/resources. A nonvariable fact must be fixed by equal original bounds or supplied through a trusted registered flat JSON binding snapshot whose exact bytes hash to an original input digest. The host must identify the approved binding snapshot, not select arbitrary JSON input or accept a solver-provided fact. The report includes the selected fact digest and a scoped canonical witness digest. S10 must retain the catalog/source binding and verified report; the public result type alone is not an authenticated certificate.

Exact independent rational arithmetic uses BigInteger and canonical reduced fractions bounded to 256 digits per numerator/denominator; no floating-point rounding. Evaluates the original DAG iteratively, including literals, symbols, all declared arithmetic and comparisons, integer/instant integrality, bounds and all original hard predicates. M04 source-model measurement admission is reused as the authoritative type/scale check; no lowered expression or compiler conversion is reused. Evaluates every soft predicate and reports its violated penalty separately, never inventing penalty-to-objective mapping or summing mixed units. All original objective expressions recompute in their own unit/currency and lexicographic order, preserving weight/tolerance metadata; report must match exact value, not merely be within tolerance. Unknown capability tokens and staged uncertainty fail closed: the current S01 single assignment does not encode scenario-specific recourse/nonanticipativity. No missing or unsupported semantic surface becomes verified. Nonzero tolerances do not establish proof.

PilotVerifier independently checks the deterministic original production specification: explicitly registered machine/calendar records, mandatory integer starts and duration, release/horizon/hard due, precedence, half-open machine occupancy and downtime, exact multi-material stock prefixes with receipts before starts at the same tick, and weighted tardiness in the frozen objective unit and optional currency. Reject missing/duplicate IDs, undefined materials/machines, mixed units, negative quantities/weights and overlapping calendars. Work is based on frozen source facts, not the solver's lowered rows. The actual V01 wowdi.factory.source/1 input is admitted through FactoryAdmission and hashed and must be registered among original input digests and bound to the same tenant/model/revision/time basis. M04 validates the frozen model catalog and material unit registration. No public DTO/schema is changed; V01 owns source admission; M10/V03/S12 own authoritative mapping from the original UDIR revision to the selected factory input. The pilot report certifies this source profile only, not arbitrary unrelated UDIR objectives or extra policies. Additional stability, stochastic recourse, changeovers and alternative machines require their own approved original source contracts; never silently treat them as covered.

Tests include exhaustive 242 start pairs across the two documented factory examples against a separately written tick-by-tick oracle (expected minima 3 and 12), 15 integer capacity/cost candidates, source/tenant mismatch, fractional and invalid assignments, source/solver fact substitution, exact objective mismatch, soft penalties and all objective observations, receipt-at-start and early stock consumption, precedence and calendar counterexamples. Run locked restore, Release tests and Traceability; no backend invocation. All fixture data are synthetic. Four actual V01 fixtures (baseline, outage, multi-material, no-stock) are also verified directly without Dispatch. Independent S05 evidence classification, M10/V03/S12 authoritative source selection and runtime mapping and S10 immutable report publication remain integration gates. The deterministic verifier is usable for supported UDIR; do not claim complete scenario or production source integration from this component alone.
