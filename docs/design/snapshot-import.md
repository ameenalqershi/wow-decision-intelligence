# I02 — CSV/JSON snapshot staging and mapping preview

Scope #56 / REQ-I02 / TC-I02-A. I01 is the source manifest contract and M10 is the authoritative UDIR import. The specialized API-MAPPING logical profile and UI20 define preview, diagnostics, provenance, target type/unit, required/null flags and no partial commit. This library implements the application-level preview/staging seam, not an HTTP wire layout, persisted mapping registry, synchronization transaction or generic model compiler.

## Trust and staging

MappingPreview obtains Write permission for the requested tenant/model via E01 before looking up a registered immutable connector/schema/mapping/stream. The registry must authorize the complete actor/model/connector key; it supplies registered manifest bytes and target schema, not an arbitrary caller manifest. A foreign or mismatched stream is absent. Host supplies IAuthorizedMappingRegistry, TenantAccess and mapping preview admission quotas; no vendor credential resolution or network access. The pure SnapshotImport.Stage is an internal-trust boundary for the host, never an authorization mechanism. It copies source and manifest bytes, validates I01 and its request scope, and permits snapshot mode only. Exact target schema/version and field identity/type/unit/required/null agreement are mandatory. Required target fields must be mapped. Unregistered transforms are rejected; only declared identity 1.0 is implemented. No arbitrary scripts or implicit conversions. Target constraints can additionally require an integral, nonnegative or strictly positive numeric value. The host must register the versioned target profile and its contextual domain constraints; the generic library does not invent a universal schema or approve target fields. For example the pilot F-DURATION is an integral positive minute quantity and must also fit the model horizon; F-WEIGHT is nonnegative in the frozen objective currency. The test target is a synthetic staging profile, not the final factory wire DTO. Model horizon/currency/reference semantics belong to the target model builder and M10/domain admission.

## File formats and exact values

Both formats use strict UTF-8 (optional UTF-8 BOM); other encodings are explicitly rejected. CSV uses a declared delimiter (comma, semicolon, tab), decimal separator (dot or comma, not the delimiter), header with unique ordinal field names, RFC 4180-style escaped quotes and quoted multiline fields, LF or CRLF. No heuristic delimiter/locale detection. A bare unquoted backslash-N denotes explicit null; quoted backslash-N is literal text; empty text is empty, not null or zero. CSV rows must match header width. JSON is a single array of flat scalar objects, case-sensitive keys, no duplicates or nested arrays/objects, numbers represented as JSON numbers (not strings), booleans as booleans, null explicit. Missing fields are distinct from explicit null. Unmapped source fields are not returned. Empty snapshots reject rather than implicitly deleting records.

Text preserves Unicode; source keys must be nonempty bounded strings, exact case and order. Timestamps use explicit manifest policy: UTC Z, explicit offset (or Z), or unambiguous local timestamp in a named zone. DST gaps and repeated local times fail. Source timestamp retains original spelling plus normalized UTC. Numeric values normalize lexically to exact decimal strings (up to 256 digits, no exponent, grouping, leading plus, rounding or floating-point conversion); integral values and negative zero are normalized. Numeric strings are component values, not a new public wire schema. Unit labels are retained and must agree exactly. No implicit exchange rate or unit conversion. Generated UDIR, if produced by a registered target builder, must pass ValidateGeneratedModel (M10 compatibility/schema/domain + exact tenant) before registry publication. The generic file reader does not pretend that arbitrary rows are a valid UDIR model.

## Output, repeat ingestion and bounds

Rows sort by ordinal serialized composite source key; mapped fields sort ordinally. Duplicate key within the snapshot fails the entire stage, even for identical duplicates. The original SHA-256 covers exact input bytes; semantic SHA-256 covers trusted stream, registered manifest digest, canonical target-profile digest and sorted normalized rows including original timestamp provenance. Reversed row order, JSON property order and equivalent decimal lexical spellings preserve semantic identity; reordered source bytes have different original digest. A changed registered manifest or target profile intentionally changes identity. This digest is a deterministic receipt candidate, not a durable idempotency guarantee; I04 owns transaction/checkpoint/receipt replay and publication. Never discard original source provenance merely because the semantic digest matches.

No partial snapshot is returned if a row fails. Diagnostics contain logical row number (1-based data row, 0 for file/header), stable target field and error code, never raw rejected values, file contents, credentials or cursor. Recoverable row-width and semantic errors accumulate; fatal syntax/encoding/JSON shape stops scanning. Diagnostic cap 1024; failure remains atomic. Conservative limits: 4 MiB source bytes, F05 manifest envelope limit, manifest row bound up to 10,000, 4096 fields/record, 8192 characters/cell, JSON depth 16, conservative normalized output budget 8 MiB (including expansion). Cancellation checked during scan; host enforces total concurrent memory, request duration, rate limits and storage admission. Preview returns mapped values only to authorized scope; all rows and identifiers are tenant-confidential and must not be logged.
