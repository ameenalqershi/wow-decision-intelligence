# S07 — Worker resource governance

Scope #32 / REQ-S07 / TC-S07-A. ADR-001, resource governance and S01 contracts remain authoritative. No solver, lowering, compiler, verifier or database dependencies introduced. A trusted host resolves the admitted immutable input, validated capability manifest, worker binary and arguments; never bind executable paths, working directory, environment or arguments directly to DML/HTTP. The frozen SHA-256 is a binding identity, not proof that the host actually supplied the corresponding bytes: S12/RT01 must materialize read-only input and verify the digest before launch.

## Scheduling and local leases

WorkerGovernor is a bounded, thread-safe host-local admission ledger. A configured tenant has its own thread/core-equivalent, reserved memory, running and queued caps; unknown tenants and impossible reservations reject. Global capacity is configured below available host capacity to leave headroom. No allocation derives from untrusted resource claims without host policy. Admission keys include tenant/model/revision/run, immutable request and frozen input digest; exact retries are duplicates, different inputs conflict. Queue and terminal ledger sizes are bounded. FIFO within a tenant, round-robin across eligible tenants. If the next eligible head fits its tenant but lacks global capacity, its turn is reserved rather than bypassing it indefinitely with small jobs; this deliberately permits global head-of-line blocking. No claim of weighted fairness or throughput superiority.

Deadline is monotonic and covers queue, execution and cleanup. Acquire reserves threads and bytes atomically. Epoch + increasing fence and immutable request identify a local attempt. Beginning execution is single-use and refreshes the remaining budget. Cancellation/expiry before launch releases reservation; after launch it revokes the fence but retains resources until the boundary confirms cleanup. Unconfirmed cleanup quarantines capacity and requires explicit trusted reconciliation. Retry of a failed, cleaned attempt is explicit and retains the original deadline and frozen request, with a new fence. Terminal outcomes remain tracked until the host durably acknowledges them; a durable job ledger must deduplicate re-admission after acknowledgement and across process restarts. Local fence is not a cross-host lease. No publication authority from a worker: the single eligible candidate goes to the independent verifier, then S12/E03 must atomically check durable fence, tenant, revision and idempotency before publishing. Timeout/cancelled/failed returns no new candidate; previously independently verified incumbents remain host-owned. A nonzero exit or timeout never implies mathematical status.

## Actual process boundary

The trusted C# bootstrap waits for a one-time stdin gate before starting the registered adapter. The parent establishes the OS scope first; no solver process runs outside it. The environment is cleared except required Windows system paths, arguments are passed without shell expansion, stdout is bounded, stderr bounded and discarded, raw subprocess messages are not logged. Deadline and external cancellation stop the scope; no candidate until the scope is empty and the bootstrap exits. Leftover descendants after a successful exit invalidate the candidate. Cleanup has a separate bounded deadline and failure quarantines capacity. This is a resource boundary for qualified native adapters, not a hostile-code sandbox: E07 owns restricted identity, filesystem, network and credential isolation. The trusted bootstrap binary, allowed executable registry, read-only working data and directory ACLs must be protected by deployment.

Linux: require an explicitly delegated cgroup v2 subtree with cpu, memory and pids enabled; refuse unavailable configuration. Each run creates its own group with cpu.max core-equivalent cap, memory.max, swap disabled, OOM group, pids.max. Attach bootstrap before release. Kernel cgroup.kill and populated check cover the group including descendants. CPU comes from cpu.stat usage_usec; peak is cgroup charged memory, not RSS. Never alter global cgroup settings; delegation setup belongs to E06. Windows: Job Object sets kill-on-close, aggregate committed-memory limit, process count and CPU hard cap derived from active processor count; attach before bootstrap release, verify membership, terminate job and confirm active process count zero. CPU comes from job user/kernel accounting; peak job commit is not RSS. Unsupported nested-job policy or OS fails closed. Both metrics carry explicit scope-memory kind, and S01 PeakBytes remains null rather than mislabel RSS. Reserved core-ms is threads times wall time, distinct from measured CPU. Queue waiting is not charged as execution core time. No use of Redis.

## Evidence and remaining gates

Local command: build Runtime.WorkerBootstrap and Runtime.Governance.Fixture in Release, set WOWDI_TEST_DOTNET to absolute dotnet binary, WOWDI_TEST_BOOTSTRAP and WOWDI_TEST_FIXTURE to absolute respective DLLs; run dotnet test tests/Runtime.Governance/WowDi.Runtime.Governance.Tests.csproj -c Release --filter 'Category!=OSContainment'. These tests include actual managed fixture subprocesses (success, nonzero exit, bounded output, cancellation and timeout) with a test-only cleanup scope; not proof of kernel caps or arbitrary descendant isolation. Scheduler tests cover 100 competing admissions, bounded queues, 20 concurrent acquisition attempts, duplicate completion, fairness, timeout, quarantine, retry and stale epoch/fence. Linux host's service subtree exposes memory/pids but does not have the required CPU delegation; no attempt to alter shared host configuration. The mandatory OSContainment suite tests aggregate memory rejection, actual CPU accounting under one core-equivalent and cancellation after an actual child begins. Hosted Linux uses an isolated disposable systemd delegated service; Windows uses actual Job Objects. Neither platform cap is qualified until those tests run successfully. No production throughput or RSS claims.

Downstream S08/S12/E05/E07/UI10/UI11/NUM04 must consume only the truthful termination, budget and metric semantics; no shared wire fields changed. S12/E03 durable database lease and recovery, E07 restricted adapter identity/egress, E06 deployment delegation/roles and actual qualified native adapter integration remain necessary. S07 remains open until required platform acceptance evidence and review; do not close merely because component tests pass.
