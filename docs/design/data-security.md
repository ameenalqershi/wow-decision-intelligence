# SEC01 — Secure data movement and retention

Scope: #148 / SEC01-01 through SEC01-05, DIR-SEC01-1, TC-SEC01-A/B. Component implementation and reference conformance, not enterprise deployment qualification. No mathematical schema, shared wire API, planning or vendor contracts changed.

## Entry points and authorization

Register a host-owned IDataMovementPolicy (deny by default), the E01 TenantAccess and protected denial audit sink, TimeProvider, two separate singleton TenantAdmissionLimiter instances (import and job admission), and DestinationPolicy populated from trusted tenant configuration. DataMovementGate requires both model authorization and an explicit movement grant; View/Write alone is insufficient. Import requires Write, redacted export View, retention Write, destination authorization Execute, job admission Propose. These are component-level mappings pending final server API integration. Do not accept a policy grant, actor, limit or destination registration from untrusted request data.

SecureTransferGate checks authorization before reading import bytes and applies an independent per-tenant rate budget. Job admission also uses its own tenant budget. Each limiter is bounded in number of tracked tenants, uses a monotonic clock and refuses new tenants when all slots are live. No active window eviction. A fixed window permits bursts at window boundaries; distributed budgets, global concurrency/memory ceilings and request timeouts must be enforced by the host/worker admission layer (E08/S12). These counters are process-local and reset on restart; they are not a distributed quota.

## Archive staging

BoundedArchive accepts ZIP bytes and stages only regular file entries in memory, without filesystem extraction. It checks actual compressed input bytes, declared and observed decompressed lengths, member CRC-32, total expanded bytes, per-entry bytes, entry count, cancellation and path safety before returning a complete immutable result. CRC-32 detects archive corruption; it is not a cryptographic authenticity guarantee. No partial result on failure. Reject absolute paths, traversal, backslashes, empty/dot segments, Windows device names/alternate streams, case-colliding duplicate names, file/directory prefix collisions, symlinks and reparse points. ASCII relative filenames only; directory entries are not supported. Do not recursively expand nested archives or interpret entry contents as executable code. The import consumer must allowlist expected names, validate schema/encoding, provenance and data, then commit atomically; this component is not a CSV/JSON schema parser.

Default limits: 8 MiB compressed, 16 MiB expanded, 4 MiB per entry, 128 entries. Hard configuration ceilings: 32 MiB compressed, 64 MiB expanded, 1024 entries. These conservative bounds are not measured throughput guarantees. Host must budget multiple concurrent staging operations, enforce HTTP body/timeout limits, and reject unknown archive formats before processing. No filesystem writes by this library.

## Export and retention

EvidenceMovement authorizes by exact tenant + model before the repository is queried; the trusted actor's tenant replaces caller tenant in the full key (tenant, model, revision, evidence). Missing and foreign records return no data. Only immutable source records from the verified-evidence store are eligible. Source bytes must match the stored SHA-256 and size limit. The initial redacted export is deliberately limited to revision/evidence IDs, source digest, mathematical status and redaction marker; it is not a complete replay bundle or mathematical proof. IDs must be opaque and safe, not customer names or secrets. Output has an independent digest; never represent redacted bytes as the original evidence. No arbitrary metadata, connector credentials, source payload or generated text is exported.

IEvidenceMovementStore is a required host port. CommitExportAuditAsync must atomically check full key, immutable digest and unexpired record and append a protected audit before bytes may be returned. An unavailable audit sink or changed/deleted record fails closed. Each new download must reauthorize. Audit includes full scoped key, verified issuer/subject, fixed action and time; protect audit access and retention separately. Host supplies correlation logging without sensitive request contents. EvidenceRetentionPolicy disallows deletion before expiry, under legal hold or while references exist. ExpireAsync must recheck that policy in one store transaction, delete bytes only, preserve immutable tombstone/reference identity and append audit atomically. A race must not produce two logical removals or a dangling reference. Do not expose raw store operations as public endpoints. A database implementation must coordinate locks/foreign keys with reference creation and audit writes; a pure decision or in-memory test does not prove that behavior.

## External destinations and secret handling

DestinationPolicy checks an exact tenant-scoped canonical HTTPS DNS endpoint, no userinfo/query/fragment/percent encoding, IP literals, loopback or .local host. Approval is only an application policy check: it does not resolve DNS, authorize an external decision, make HTTP requests, or guarantee egress safety. Transport must enforce allowed resolved IPs at connection time, disable redirects or reauthorize each hop, pin TLS/hostname, and handle DNS rebinding and private/metadata networks per F04. I03/I04/E04 own that network integration. Never pass raw connector credentials into this library; resolve by authorized reference inside connector scope. Avoid logging paths, raw archives, tokens, cursor values or external errors. Export does not bypass approval or enable external writes.

## Durable PostgreSQL integration (SEC01 / E02)

The optional WowDi.Enterprise.DataSecurity.Postgres project implements IEvidenceMovementStore using EF Core 10/Npgsql and a separately versioned wowdi_security schema. Apply EnterpriseDb migrations first, then SecurityDb migrations; never run them independently on every server instance. The external E02 revision entity is excluded from security migrations, but its tenant/model/revision FK is enforced by PostgreSQL. No E02 schema is rewritten.

Artifacts use the full tenant/model/revision/evidence key. Original bytes and SHA-256 are registered only through RegisterPublishedAsync by a trusted S10 evidence publisher after independent verification. This is not a mathematical evidence producer or public endpoint; it must not accept a user-supplied mathematical status as verified. Idempotent exact publication retries preserve the first artifact, and purged identities cannot be resurrected. S10 owns the authoritative evidence record and must integrate this port rather than create an unsynchronized duplicate. Reference rows use the complete artifact key and an explicit reference ID; acquire/release and purge lock the same row. Legal hold changes use a separate trusted, audited policy operation. Expiry is checked against PostgreSQL clock_timestamp, not a caller-supplied time. A retained artifact can be expired for export while still protected from deletion by references or hold.

Redacted export commits its audit only after rechecking the immutable digest and unexpired bytes under a database lock; audit failure returns no data. Expiry sets bytes to null and a durable purged timestamp in the same transaction as the audit, preserving metadata and key. Foreign keys, checks and database triggers guard against dangling references, unsafe updates, purge without matching audit and accidental audit/tombstone deletion. Retention records are not cryptographic tamper-proof against database superusers. Production roles must prohibit arbitrary SQL, restrict direct table writes (particularly hold/registration/reference operations), protect audit SELECT access, separate migration and backup roles, and qualify grants/RLS in E06/RT02. Physical erasure from historical backups/WAL requires the separately governed encrypted backup lifecycle (SEC03), not merely setting a column to null. No direct user route is added for registration, reference changes or hold changes.

The actual PostgreSQL tests create uniquely named disposable databases and apply both migrations. They verify persisted audit, atomic rollback on an injected audit failure, full FK enforcement, exact registration, reference/hold protection, concurrent retention (20 attempts, one removal), tombstone permanence, and direct database guard checks. A test-only Kestrel HTTP host exercises the production E01 JWT bearer pipeline with locally signed tokens and synthetic OIDC discovery/JWKS, actual E02 model registration and the real PostgreSQL movement store; authorized export contains redacted fields only and denies missing/expired tokens, foreign tenant and missing movement permission. These fixture routes are not a proposed public API-EVIDENCE contract. Tests do not contact a real IdP or external connector. The other DB-only tests use minimal FK anchor records as fixtures.

Run locked restore and Release test suites in tests/Enterprise.DataSecurity and tests/Enterprise.DataSecurity.Postgres (the latter requires WOWDI_PG for a disposable PostgreSQL 16 server with CREATEDB). No fallback to an in-memory database. CI uses PostgreSQL 16 plus Linux/Windows component tests. The production S10 verified publication, E05 durable denial audit, S12 final endpoint mapping and I03 transport/egress wiring remain integration gates; #148 stays Active/Draft until those are qualified. No full deployment or compliance certification is claimed.

SEC01 also supplies SecureSnapshotPreview for I02 CSV/JSON: the explicit movement grant and shared import-rate budget are checked before any body bytes are read, the actual stream is bounded to 4 MiB, and the live authorized MappingPreview registry is rechecked before returning normalized rows. Hosts must register the same import limiter for archive and snapshot requests, and not expose the ungated component directly. The API-MAPPING/S12 route remains owner-gated.

## Restore, concurrent export and scope compatibility qualification

The PostgreSQL fixture suite now uses matching major-16 pg_dump/pg_restore binaries and restores a custom-format backup into a fresh uniquely named database. The test verifies both migration histories, retained bytes and digest, legal holds, references, tenant-specific movement audits, immutable tombstones and post-restore export. The restored database must still reject audit deletion, tombstone resurrection and late references. This is a logical backup/restore conformance test, not production RPO/RTO, point-in-time recovery, encrypted backup retention or reconciliation against an external deletion ledger. Production recovery must prevent resurrection from older backups and reapply retention/hold decisions before serving restored data; SEC03 and E05 own those operational gates.

The concurrent workload runs 32 export audit transactions divided equally between two tenants. It verifies 16 correctly scoped audit records per tenant. A separate transaction holds an artifact row lock while retention is cancelled; no purge or purge audit may survive the cancellation, and a subsequent retry must succeed exactly once. This is a bounded concurrency/failure test, not a throughput or resource saturation benchmark.

EvidenceKey now validates tenant/model/revision identifiers using the E02 256-character ordinal Unicode scope rules (including strict UTF-8 and no control characters or surrounding whitespace). Evidence handles remain opaque ASCII. This fixes a prior mismatch with the field dictionary and E02 for Arabic identifiers. Actual HTTP/JWT and PostgreSQL integration uses an Arabic tenant identifier. Revision and evidence identifiers must still be safe identifiers rather than secrets or customer free text. Export reauthorizes the same actor and movement grant after reading/hashing the artifact and before audit commit. This closes the observed revocation-during-read gap; authorization and data mutation are not an atomic distributed policy transaction, and S12/E05 must define the final policy-revision and denial-audit semantics.

## Audited hold transitions and import revocation

ZIP staging now checks the same authenticated actor and live import grant again after archive validation and before returning staged bytes. CSV/JSON checks the actor after reading the bounded stream and after registered mapping preview. A revoked grant discards the result; the consumed admission permit is not refunded. These checks do not create an atomic distributed authorization transaction; final publication and policy revision semantics remain S12/I04.

The second EF migration AuditedHoldTransitions adds nullable hold_changed_at to existing artifacts without rewriting the initial migration. A deferred PostgreSQL constraint trigger requires every actual legal-hold change to carry a fresh, strictly increasing database timestamp and a matching same-artifact HoldSet/HoldReleased audit within the transaction time window. Updating the timestamp without changing the flag fails. The store writes the flag, timestamp and audit atomically under its existing row lock. Exact no-op retries do not append another audit. Existing initial hold flags remain intact and their timestamp is null until a subsequent transition; trusted publication remains an S10 integration gate. Database roles capable of fabricating audit inserts or disabling triggers remain privileged and require E06 qualification. The actual PostgreSQL regression verifies unaudited release, stale audit replay, rollback on audit failure, correct repeated transitions and retention protection. Both migrations apply on fresh databases and the existing logical restore test runs with both migrations; a separate populated pre-upgrade database qualification remains unverified.
