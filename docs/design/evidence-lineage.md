# S10 — Immutable run evidence and lineage

Scope #35 / TC-S10-A. The independent evidence layer depends on S04/S05 and the M11 immutable revision registry, never on a solver adapter, compiler lowering, HTTP or enterprise database. The host selects an authorized immutable revision and authoritative admitted run binding, the exact frozen facts/catalog and the actual qualified solver report. A caller-supplied scope, hash, status or proof is not publication authority.

## Evidence identity and reproducibility

The F05 envelope wowdi.evidence.run/1.0 contains the full tenant/model/revision/run scope, original canonical UDIR SHA-256, selected fact SHA-256, all registered revision input and source SHA-256 values, catalog digest, manifest/capability digest, solver-report digest, recomputed assessment digest and exact settings digest. The host-provided invocation records a distinct attempt ID, adapter package and verifier build SHA-256, compiler/planner versions, qualified profile, hardware/runtime class, logical processors, host memory, reserved threads/memory/time, seed, UTC start/end timestamps and independent enumeration budget. The original native report retains version/RID, termination, mathematical claim, tolerances, resources and evidence references. Hardware/build metadata is supplied by the trusted host, not attested by this library; do not include host names, credentials, tokens or paths to secrets. The adapter-specific settings snapshot is strict bounded JSON data and is never executed by evidence replay. The host must provide an approved nonsecret settings schema, not arbitrary client values.

EvidenceId is SHA-256 of the exact manifest envelope. Each blob is independently hashed; the bounded portable binary package WDIE0001 frames manifest, catalog, capabilities, original result, checked assessment and settings in that order with big-endian length prefixes, no compression, paths or executable content. Max 8 MiB, tighter per-artifact caps: 1 MiB for manifest/capabilities/result/assessment, 256 KiB catalog, 64 KiB settings. OriginalSha256 hashes the entire package and is NOT EvidenceId. This distinction is required by SEC01. The package intentionally references original model/source content in M11/E02 rather than duplicating every sensitive input; replay requires the exact authorized revision. Revision input count capped at 1024, sum of input bytes capped at 64 MiB for this profile. Object properties are sorted ordinally for deterministic internal canonical JSON; preserve array order. This is not a general RFC 8785 implementation.

Capture validates the producer scope, invocation, revision input hashes and selected catalog; recomputes S05 assessment rather than accepting caller-supplied mathematical status. Replay validates the expected evidence ID and package hash from a trusted ledger, the strict F05 envelope, all artifact digests and current frozen revision, then reruns S05 and compares canonical assessment bytes. A rehashed false assessment still fails replay. Replayed computation is independent verification, not rerunning the native solver. Profile wowdi.s04/1+wowdi.s05/1 must match; matching a host-provided verifier binary hash is not a binary attestation. Future verifier changes require an explicit version/replay compatibility policy. Unknown and rejected results may be retained for audit, but cannot become verified or proposal-authorizing records. S05 currently proves the supported deterministic single-objective profile; unsupported models remain rejected; no general mathematical proof or native adapter qualification. Hashes detect content mismatch, not authenticity against an attacker who can replace the authoritative ledger and every artifact.

ExportAuditReport yields an authorized F05 audit document with scoped IDs, input digests, invocation, solver identity, status/termination, evidence levels, units, gaps, tolerances and enumeration counts; no raw source, settings or witness assignments. It still contains confidential metadata/objective values and is NOT SEC01's redacted external export. Export of either package or audit report requires host authorization.

## Storage

SqliteEvidenceStore owns a separate evidence database in the selected local workspace; no changes to M11 schema or user_version. Verify storage application ID/version; reject unrelated files. Full tenant/model/revision/evidence primary key and tenant/model/revision/run/attempt unique constraint. Exact retries converge, conflicting retries fail. Store manifest and all blobs in a single immediate transaction; verify against actual M11 before commit. Parent evidence is optional, same tenant/model/revision, preexisting, and constrained by a composite FK; no update or delete through the application, immutable-row triggers add defense in depth. Parent identity is rechecked on load. Revision history is immutable in M11; because these are two independent SQLite files, no cross-database FK or atomic cross-file restore is claimed. RT01 must preserve both files with a coordinated quiesced snapshot. Filesystem ACLs and host-controlled paths are required; SQLite file owners remain privileged. This store is not a retention implementation or an enterprise job ledger.

Enterprise consumer: S12/E02 must resolve a real authorized EnterpriseRevision and adapt its exact document/graph/input bytes to the immutable revision input of EvidenceRecord. The trusted fenced publisher passes EvidencePackage.Export(record) and its SHA-256, EvidenceId and independently assessed status to the existing SEC01 RegisterPublishedAsync port; do not duplicate that PostgreSQL store or accept user-provided status. Publication must enforce durable attempt fencing, transactional lineage/reference registration, retention/audit policy and proper authorization. A local store success is not evidence of enterprise publication. #148 owns its redaction/retention/actual PostgreSQL integration; #36 owns workflow transitions; #37 owns final API and durable worker. The package is a bounded integration contract, not a new public REST route.
