# E05 — enterprise operations

Scope #79 / TC-E05-A. E02 owns frozen registry and durable job admission; S07 owns process resource governance; S12/E03 own orchestration and authoritative durable fences. E05 owns observability and operations data, not a second job state machine.

The E01 denial audit sink uses a separate PostgreSQL schema and EF migration history. It stores trusted actor tenant when present, domain-separated HMAC-SHA256 subject/correlation pseudonyms, fixed allowlisted action and server UTC timestamp. Unknown actions are collapsed, unknown actor is not guessed, and no raw subject, token, URL, payload, exception, or target tenant is persisted. The host supplies a separate 32-byte high-entropy key; it is not persisted. Denial write failures propagate to E01. Tenant identifiers are protected metadata, not anonymous. Key custody/rotation, exporter configuration and production role grants remain deployment gates.

RunUsageRecorder is a trusted host port consuming S07 WorkerLease and BoundaryResult, never a public client input. Each cleaned attempt (including failed/cancelled/timed-out) uses the full tenant/model/revision/job key, local epoch and increasing fence; the input digest and resource observations remain immutable. Actual E02 job and revision foreign keys and an insert trigger enforce the scope; exact concurrent retries converge; different contents reject. It does not certify the mathematical result or confer durable publication authority. S12 must bind the frozen input digest to the authoritative admitted job and record actual measurements through the durable worker flow, including reconciliation of lost workers. Unknown cleanup cannot become a successful usage observation. Distinguish reserved core-ms (threads times elapsed wall time), measured CPU ms and missing observations. Peak charged cgroup memory and Windows job commit are separate labeled measures, not RSS. Do not sum peak metrics across platforms or manufacture a monetary rate; per-tenant model-scoped resource attribution is the input to a separately approved tariff policy.

The worker.usage.record ActivitySource is OpenTelemetry-compatible. The span emits only the fixed termination enum and availability flags, never customer input or tenant/model/job IDs. The optional trace ID is persisted alongside the full scope in the protected usage ledger. Host exporters must disable sensitive SQL/HTTP payload capture and untrusted baggage; the component does not install a global exporter or claim an end-to-end production trace pipeline. UsageReader requires E01 model View before lookup and again before returning, uses repeatable-read aggregate queries, distinguishes missing CPU from observed zero and keeps memory measures distinct. The date window is bounded to 366 days; an aggregate is not a tenant-admin grant. Public route mappings remain S12.

DenialRetention is a privileged host maintenance port with explicit cutoff, scope and operation ID. Null tenant means only the unknown actor bucket; never a wildcard. Batches are bounded to 1000, select old rows with row locks and skip locked rows, and record deletion and immutable receipt atomically in PostgreSQL. Exact operation-ID retries return the first count without more deletion; changed scope/cutoff/limit conflicts. Caller must resolve approved retention policy and legal preservation obligations before invocation. The SQL SECURITY DEFINER function has a fixed search path, fully qualified tables and no PUBLIC execute. No arbitrary SQL or public endpoint. Runtime audit writer should receive only INSERT on denials; maintenance role only EXECUTE on expire_denials, never direct DELETE; usage writer limited INSERT/SELECT on run_usage and SELECT on E02 scope; read-only report role SELECT only. Separate migration owner; no superuser/DDL privilege in runtime. Immutable row triggers protect usage and retention receipts. Direct denial deletion remains possible for table owners or roles wrongly granted DELETE, and no application guard constitutes protection from database superusers. E06 must qualify role grants and policy custody. The retained usage ledger itself requires a separately approved archival policy before production.

Apply E02 migrations first, then OperationsDb migrations. The second migration also owns raw SQL trigger/function/trace/receipt definitions; these are not EF-managed entities. Run locked restore and Release tests with WOWDI_PG identifying disposable PostgreSQL 16 with CREATEDB; pg_dump and pg_restore major 16 required. Tests create/drop uniquely named databases. Six tests cover concurrent redacted denials, migration/failure propagation, 24 competing usage retries, trace tags and tenant scope, 12 retention retries with atomic rollback on receipt failure, logical backup/restore into a fresh database, and actual Kestrel JWT plus E02 revision and job admission with authorized usage aggregates and durable denials. Actor keys, OIDC discovery, job requests and measured-result values are synthetic fixtures; PostgreSQL, HTTP and JWT signature validation are real. S07 separately qualifies actual OS resource accounting; no measured production throughput or monetary cost claim. Restore drill does not establish production PITR/RPO/RTO or older-backup erasure reconciliation; SEC03 owns those gates. Retain #79 Active/Draft until actual worker-to-usage, production role/exporter and policy qualification are resolved.
