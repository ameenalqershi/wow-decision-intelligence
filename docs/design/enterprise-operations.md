# E05 — enterprise operations (work in progress)

Scope #79 / TC-E05-A. This initial slice implements the E01 denial audit sink in a separate PostgreSQL schema and EF migration history. It stores trusted actor tenant when present, domain-separated HMAC-SHA256 subject/correlation pseudonyms, fixed allowlisted action and server UTC timestamp. Unknown actions are collapsed, unknown actor is not guessed, and no raw subject, token, URL, payload, exception, or target tenant is persisted. The host supplies a separate 32-byte high-entropy key and configures the sink explicitly. The key is not persisted. Key custody and rotation, permissions and retention are still release gates. Tenant identifiers are protected database metadata, not anonymous; no untrusted API may query this context. Failures propagate to E01 and do not silently permit operations.

The current migration and tests establish only durable denial recording, repeatable migration, failure propagation, and tenant-separated pseudonyms under concurrent writes. Audit deletion protection, controlled retention, restore drill, authorized scoped operations, model/run telemetry and measured resource cost attribution remain outstanding. Do not deploy or close #79 based on this slice. Runtime and migration roles must be separate; no UPDATE/DELETE privilege for the audit writer. E05 will coordinate retention with SEC01, rather than duplicate evidence rules.

Run locked restore and the Release tests with WOWDI_PG identifying a disposable PostgreSQL 16 server with CREATEDB. Each test creates and drops a unique database. Synthetic actors/secret only.
